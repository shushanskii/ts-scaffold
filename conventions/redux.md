# Conventions — Redux Toolkit + Saga

State management for React apps. Assumes [`core.md`](./core.md) and [`react.md`](./react.md);
portable to any RTK project.

## Stack additions

- **@reduxjs/toolkit** — the store and Immer-backed slices
- **react-redux** — `Provider`, `useSelector`, `useDispatch`
- **redux-saga** — all side effects; the thunk middleware is switched off
- **reselect** — imported as `createSelector` **from `@reduxjs/toolkit`**, which re-exports it.
  Do not add `reselect` as a direct dependency: a second copy at a different version defeats the
  memoization it exists for.

## The flow

One direction, no shortcuts:

```
component → hook → dispatch(intent from actions/) → saga → put(slice action) → reducer
                 ↖──────────────── selector ←──────────── store ←──────────────┘
```

- **The UI dispatches intents only.** An intent is declared by hand in `actions/<entity>` and is the
  only kind of action a hook may dispatch.
- **Slice actions belong to sagas.** They are generated by `createSlice` and reach the store solely
  through a saga's `put`. A component or hook that dispatches one is a bug.
- **The UI reads through selectors.** Never `useSelector((state) => state.todos.items)` inline —
  call a named selector from `selectors/<entity>`.

The point is that every state change has one entry point per entity and one place to look for what
happens next.

## Buckets

On top of the layers in `core.md`:

```
src/
├── actions/<entity>/index.ts    # enum of intent types + their creators — hand-written
├── reducers/<entity>/index.ts   # createSlice: state, initialState, generated slice actions
├── sagas/<entity>/index.ts      # watchers + workers; the only place slice actions are dispatched
├── store/index.ts               # configureStore + saga middleware; exports RootState, AppDispatch
├── selectors/<entity>/index.ts  # plain reads + memoized derivations, typed against RootState
├── hooks/<entity>/index.ts      # selectors in, memoized intent dispatchers out
└── components/<Name>/index.tsx
```

Direction: `types → actions → reducers → sagas → store → selectors → hooks → components`.

`selectors/` sits after `store/` because it is typed against `RootState`. Keeping selectors out of
`reducers/` is what lets `store/` import `reducers/` without a cycle.

## Where core.md bends

`core.md` says reducers are framework-free and state is never mutated. Inside `reducers/` those two
do not apply:

- **Immer drafts are mutated on purpose.** `state.loading = true` is the sanctioned style. The
  `State` interface stays `readonly` for every consumer; only the draft is writable.
- **`reducers/` imports `@reduxjs/toolkit`.** That is the one framework import allowed in the layer.

The enum rule survives intact where it counts: intent types in `actions/` are hand-declared enum
members, never raw strings. Slice action types are generated by `createSlice`, but nothing outside
a saga ever names one, so they stay an implementation detail.

## Rules

- **Memoize what derives, not what reads.** A selector that returns something already in the store
  (`state.todos.items`) is a plain function. A selector that filters, maps, sorts, or assembles an
  object goes through `createSelector` — otherwise it returns a new reference on every render and
  every `memo`-ed consumer below it re-renders. Compose derived selectors from the plain ones rather
  than reaching into state twice.
- **Namespace intent values** — `"todos/load"`, not `"load"`. Redux action types share one global
  space, and a bare verb will trigger another entity's saga.
- **Declare action shapes with `type`, not `interface`.** Redux's `UnknownAction` carries an index
  signature and TypeScript grants an implicit one to type aliases only; an interface fails to
  dispatch with a confusing error about a missing index signature.
- **A slice exports its reducer, its actions, and `initialState` — nothing else.** Assembling them
  is `store/`'s job, so `reducers/` never imports `store/`.
- **Sagas own every side effect.** `configureStore` runs with `{ thunk: false }`.
- **Hooks return state plus a `useMemo`-ed action object**, so leaf components stay `memo`-able.
- **Immer's no-op guarantee is a test contract.** A reducer that changes nothing must return the
  identical state object — assert it with `toBe(previous)`.

## Testing

A slice reducer is a pure function, so it is tested exactly as `core.md` describes: build state as
literals with fixed ids, apply the slice action directly, assert the new state, the untouched
previous state, and reference stability on no-ops. No store, no `Provider`, no mocks.
